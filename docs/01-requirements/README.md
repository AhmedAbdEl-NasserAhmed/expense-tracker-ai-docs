# Requirements

## Purpose

Translate the agreed MVP scope into explicit system requirements before technical design begins.

## Requirement Principles

- Requirements describe what the system must do, not how it is implemented.
- Product decisions already agreed in Product Discovery and MVP Scope are treated as constraints.
- Unresolved decisions are explicitly recorded as open questions rather than guessed.
- Requirements should be testable where practical.

## Documents

- `functional-requirements.md` — system capabilities.
- `non-functional-requirements.md` — quality and operational expectations currently known.
- `business-rules.md` — financial and product rules.
- `use-cases.md` — major user/system interactions.
- `user-stories.md` — user-centered requirements.
- `acceptance-criteria.md` — testable acceptance conditions for core behavior.
- `mvp-requirements.md` — consolidated MVP requirement boundary.

## Current Status

Requirements discovery is complete for the currently identified MVP behavior. Open questions remain where the product has not yet made a deliberate decision.
