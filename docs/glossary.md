# Glossary

This document defines the business terminology used throughout the project.

Every document in this repository should use these definitions consistently.

---

# User

A person who creates an account and uses the application to understand and improve their financial situation.

---

# Financial Profile

A collection of information describing the user's current financial situation.

The financial profile includes:

- Income
- Income streams
- Savings
- Fixed commitments
- Marital status
- Recurring expense categories

The financial profile is created during onboarding.

---

# Income

Money received by the user within a specific period.

For the MVP, income is measured monthly.

Examples:

- Salary
- Freelancing
- Rental income
- Business income

---

# Income Stream

A single source of income.

Examples:

- Full-time job
- Freelance work
- Investments

A user may have multiple income streams.

---

# Gross Income

The total monthly income before subtracting any commitments or expenses.

Example:

Salary = 40,000 EGP

Freelance = 10,000 EGP

Gross Income = 50,000 EGP

---

# Fixed Commitment

A recurring financial obligation that the user is expected to pay regularly.

Examples:

- Rent
- Mortgage
- Car installment
- Loan payment
- School fees

These commitments are considered when calculating available monthly income.

---

# Available Monthly Income

The amount of money remaining after subtracting fixed commitments from the user's gross monthly income.

Example:

Gross Income:
50,000 EGP

Fixed Commitments:
15,000 EGP

Available Monthly Income:
35,000 EGP

This represents the user's starting point before considering day-to-day spending.

---

# Savings

Money the user has already accumulated and can use toward future financial goals.

---

# Expense

A financial transaction where money leaves the user's account.

Every expense belongs to exactly one category.

Examples:

- Restaurant
- Fuel
- Groceries

---

# Expense Category

A logical grouping of similar expenses.

Examples:

- Groceries
- Transportation
- Entertainment
- Healthcare

Users can choose predefined categories or create custom ones.

---

# Spending Pattern

A recurring trend identified from the user's expense history.

Examples:

- Spending more on weekends.
- Restaurant spending increasing every month.
- Transportation costs decreasing.

Spending patterns are discovered over time.

---

# Financial Goal

A future objective the user wants to achieve financially.

Examples:

- Buy a car
- Buy a house
- Build an emergency fund
- Pay off debt

Financial goals are **not** part of onboarding.

They are managed separately within the application.

---

# Recommendation

A personalized suggestion generated by the application to help the user improve their financial situation or achieve a financial goal.

Example:

Reducing restaurant spending by 20% would allow you to reach your savings goal three months earlier.

---

# Insight

An observation generated from the user's financial data.

Unlike recommendations, insights do not tell the user what to do.

Example:

You spent 18% more on transportation this month compared to last month.

---

# Dashboard

The main screen presented after the user signs in.

It summarizes the user's financial profile, spending activity, and progress toward goals.

---

# Onboarding

The initial experience where the application collects the minimum information required to build the user's financial profile.

---

# Manual Expense Tracking

The process of the user recording expenses within the application.

For the MVP, expense tracking is performed manually.

---

# MVP (Minimum Viable Product)

The smallest version of the application capable of delivering value to users while validating the core product idea.

Features outside the MVP are documented in the Parking Lot.

---

# Parking Lot

A document containing ideas intentionally postponed until after the MVP.

Items in the Parking Lot are not considered part of the current project scope.
